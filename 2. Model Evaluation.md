# Credit Risk Model Evaluation Techniques

---

# Introduction

In **credit risk modeling**, after building a predictive model (for example a **Probability of Default (PD) model using Logistic Regression**), it is necessary to evaluate how well the model performs.

Model evaluation helps answer the following questions:

* Is the model correctly identifying risky borrowers?
* Can the model distinguish between **good customers and bad customers**?
* Is the model reliable enough for **banking decision making**?
* Does the model remain stable over time?

Financial institutions use multiple evaluation metrics because **credit risk datasets are usually imbalanced** (very few defaults compared to non-defaults).

Therefore, relying on a single metric like **accuracy** is not sufficient.

This document explains the **most important model evaluation techniques used in credit risk modeling**.

---

# 1. Confusion Matrix

A **Confusion Matrix** is the fundamental tool used to evaluate classification models.

It compares:

* Actual outcomes
* Model predictions

| Actual / Predicted | Non‑Default (0)     | Default (1)         |
| ------------------ | ------------------- | ------------------- |
| Non‑Default (0)    | True Negative (TN)  | False Positive (FP) |
| Default (1)        | False Negative (FN) | True Positive (TP)  |

## Meaning in Credit Risk

| Term                | Meaning                                            |
| ------------------- | -------------------------------------------------- |
| True Positive (TP)  | Model correctly predicts a borrower will default   |
| True Negative (TN)  | Model correctly predicts borrower will repay       |
| False Positive (FP) | Model predicts default but borrower repays         |
| False Negative (FN) | Model predicts safe borrower but borrower defaults |

### Important Note

In banking, **False Negatives are very dangerous** because the bank may approve a loan to someone who will default.

---

# Example

Suppose a bank evaluates **100 loan applicants**.

|                | Predicted Safe | Predicted Default |
| -------------- | -------------- | ----------------- |
| Actual Safe    | 60             | 10                |
| Actual Default | 5              | 25                |

Interpretation:

* 60 correct safe predictions
* 25 correct default predictions
* 10 good customers rejected
* 5 risky customers approved

---

# 2. Accuracy

Accuracy measures the **overall correctness of the model**.

Formula:

```
Accuracy = (TP + TN) / (TP + TN + FP + FN)
```

Example:

```
TP = 25
TN = 60
FP = 10
FN = 5

Accuracy = (25 + 60) / 100 = 85%
```

## Problem with Accuracy in Credit Risk

Credit datasets are **highly imbalanced**.

Example dataset:

| Category    | Count |
| ----------- | ----- |
| Non‑Default | 950   |
| Default     | 50    |

If a model predicts **everyone as non‑default**, accuracy = **95%**, but the model completely fails to detect risky borrowers.

Therefore, banks prefer metrics like:

* ROC-AUC
* KS Statistic
* Gini

---

# 3. Precision

Precision measures how many predicted defaulters actually default.

Formula:

```
Precision = TP / (TP + FP)
```

Example:

```
TP = 25
FP = 10

Precision = 25 / (25 + 10) = 0.71
```

Meaning:

If the model predicts someone as **risky**, precision tells how often the prediction is correct.

---

# 4. Recall (Sensitivity / True Positive Rate)

Recall measures how many **actual defaulters the model correctly detects**.

Formula:

```
Recall = TP / (TP + FN)
```

Example:

```
TP = 25
FN = 5

Recall = 25 / (25 + 5) = 0.83
```

Meaning:

Higher recall means the model detects **more risky borrowers**.

---

# 5. ROC Curve (Receiver Operating Characteristic)

The **ROC Curve** measures the model's ability to distinguish between good and bad borrowers.

It plots:

| Axis   | Meaning             |
| ------ | ------------------- |
| X-axis | False Positive Rate |
| Y-axis | True Positive Rate  |

The ROC curve evaluates model performance **across different probability thresholds**.

### Interpretation

| ROC Curve Shape      | Meaning            |
| -------------------- | ------------------ |
| Diagonal Line        | Random Model       |
| Above Diagonal       | Better than Random |
| Near Top Left Corner | Excellent Model    |

---

# 6. AUC (Area Under the ROC Curve)

AUC summarizes the ROC curve into a **single number**.

```
AUC = Area under ROC Curve
```

Interpretation:

| AUC Value | Model Quality |
| --------- | ------------- |
| 0.5       | Random        |
| 0.6 – 0.7 | Weak          |
| 0.7 – 0.8 | Acceptable    |
| 0.8 – 0.9 | Good          |
| > 0.9     | Excellent     |

Meaning in Credit Risk:

An AUC of **0.80** means:

There is an **80% probability that the model assigns a higher risk score to a bad borrower than to a good borrower**.

---

# 7. KS Statistic (Kolmogorov–Smirnov Statistic)

The **KS Statistic** measures the maximum separation between **good and bad customers**.

Banks widely use KS for **credit scorecard validation**.

The KS value represents the maximum difference between:

* Cumulative percentage of good borrowers
* Cumulative percentage of bad borrowers

Example:

| Risk Bucket | % Good | % Bad | Difference |
| ----------- | ------ | ----- | ---------- |
| Low Risk    | 20     | 5     | 15         |
| Medium Risk | 40     | 20    | 20         |
| High Risk   | 70     | 30    | 40         |

Maximum difference = **40**

Therefore:

```
KS = 40
```

Interpretation:

| KS Value | Model Quality |
| -------- | ------------- |
| < 20     | Poor          |
| 20 – 40  | Average       |
| 40 – 60  | Good          |
| > 60     | Excellent     |

Most banks require **KS greater than 30**.

---

# 8. Gini Coefficient

The **Gini coefficient** measures the discriminatory power of the credit model.

Relationship between AUC and Gini:

```
Gini = 2 × AUC − 1
```

Example:

```
AUC = 0.80

Gini = 2 × 0.80 − 1
Gini = 0.60
```

Interpretation:

| Gini Value | Model Strength |
| ---------- | -------------- |
| 0          | Random         |
| 0.3 – 0.5  | Acceptable     |
| 0.5 – 0.7  | Good           |
| > 0.7      | Excellent      |

Typical credit scorecards have **Gini between 40% and 60%**.

---

# 9. Lift Chart

Lift measures how much better the model performs compared to **random selection**.

Example:

Suppose a bank selects the **top 10% highest risk customers predicted by the model**.

| Selection Method      | Default Capture |
| --------------------- | --------------- |
| Random Selection      | 10%             |
| Model Based Selection | 35%             |

Lift Calculation:

```
Lift = 35 / 10 = 3.5
```

Meaning:

The model is **3.5 times better than random selection** at identifying risky customers.

---

# 10. Population Stability Index (PSI)

PSI measures **model stability over time**.

It compares:

* Training data distribution
* Production data distribution

PSI helps detect **data drift**.

Interpretation:

| PSI Value  | Meaning           |
| ---------- | ----------------- |
| < 0.1      | Stable Population |
| 0.1 – 0.25 | Moderate Shift    |
| > 0.25     | Significant Shift |

If PSI exceeds **0.25**, the model may require **retraining**.

---

# When to Use Each Metric

| Metric           | Purpose                             | When to Use                        |
| ---------------- | ----------------------------------- | ---------------------------------- |
| Confusion Matrix | Basic prediction breakdown          | Initial model evaluation           |
| Accuracy         | Overall prediction correctness      | Balanced datasets only             |
| Precision        | Correctness of predicted defaults   | When minimizing false alarms       |
| Recall           | Ability to detect risky borrowers   | When minimizing missed defaults    |
| ROC Curve        | Model discrimination visualization  | Model comparison                   |
| AUC              | Overall discrimination performance  | Standard metric for classification |
| KS Statistic     | Separation of good vs bad borrowers | Credit scorecard validation        |
| Gini             | Credit scoring power                | Regulatory reporting               |
| Lift             | Model improvement vs random         | Marketing / risk targeting         |
| PSI              | Model stability monitoring          | Production monitoring              |

---

# Typical Metrics Used by Banks

In real banking systems, the most commonly used evaluation metrics are:

| Metric       | Importance                 |
| ------------ | -------------------------- |
| ROC-AUC      | Primary performance metric |
| KS Statistic | Credit scoring validation  |
| Gini         | Regulatory reporting       |
| PSI          | Model monitoring           |

Accuracy is **rarely used alone** in credit risk.

---

# Typical Credit Risk Model Validation Workflow

```
Step 1: Train/Test Split

Step 2: Train Logistic Regression / ML Model

Step 3: Generate Probability of Default (PD)

Step 4: Evaluate using ROC-AUC

Step 5: Calculate KS Statistic

Step 6: Compute Gini Score

Step 7: Validate Lift Chart

Step 8: Deploy Model

Step 9: Monitor PSI over time
```

---

# Summary

Credit risk model evaluation requires **multiple metrics** because financial datasets are imbalanced and mistakes can be extremely costly.

The most critical metrics used in practice are:

* ROC-AUC
* KS Statistic
* Gini Coefficient
* Lift
* PSI

These metrics ensure that the model can:

* Detect risky borrowers
* Separate good and bad customers
* Remain stable in production
